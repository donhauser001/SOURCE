### 2.2 详细说明

#### 2.2.1 分页功能（P1）

**问题描述**:  
色彩管理列表当前使用 `limit: 100` 硬编码，超过 100 条记录时：
- 性能下降
- 前端内存占用高
- 网络传输量大

**影响范围**:
- `/admin/colors` 色彩列表
- `/admin/users` 用户列表（潜在）
- `/admin/partners` 合作者列表（潜在）

**解决方案**:
```typescript
// 推荐：Cursor-based Pagination
adminListInfinite: adminProcedure
  .input(z.object({
    limit: z.number().min(1).max(100).default(20),
    cursor: z.string().optional(),
  }))
  .query(async ({ ctx, input }) => {
    const items = await ctx.db.color.findMany({
      take: input.limit + 1,
      cursor: input.cursor ? { id: input.cursor } : undefined,
      orderBy: { createdAt: 'desc' },
    });
    // ... 返回 items + nextCursor
  });
```

#### 2.2.3 数据导入事务回滚（P1）

**问题描述**:  
当前导入失败时，部分数据可能已写入数据库，导致数据不一致。

**影响**:
- 导入 100 条记录，第 50 条失败，前 49 条已入库
- 用户需要手动清理脏数据

**解决方案**:
```typescript
// 使用 Prisma 事务
await db.$transaction(async (tx) => {
  for (const color of colors) {
    await tx.color.create({ data: color });
  }
});
// 任一失败，全部回滚
```

4. **存储配置**: OSS/R2/CDN 配置

**解决方案**:

#### 2.2.5 操作审计日志（P2）

**问题描述**:  
管理员操作无审计记录，无法追踪：
- 谁修改了什么数据
- 何时进行的修改
- 修改前后的值

**数据模型设计**:
```prisma
model AdminAuditLog {
  id          String   @id @default(cuid())
  userId      String
  user        User     @relation(fields: [userId], references: [id])
  
  action      String   // CREATE, UPDATE, DELETE, BULK_DELETE
  targetType  String   // color, partner, user, etc.
  targetId    String?
  
  changes     Json?    // { old: {...}, new: {...} }
  metadata    Json?    // { ip, userAgent, ... }
  
  createdAt   DateTime @default(now())
  
  @@index([userId, createdAt])
  @@index([targetType, targetId])
}
```
